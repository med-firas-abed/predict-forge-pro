PrediTeq Bridge Kit

What this folder is:
- a small clean bundle to copy by USB to a MacBook
- only the files needed to rehearse or send one CSV file to PrediTeq
- it does NOT include prediteq_api/.env or backend secrets

What the MacBook does:
- reads a local CSV file
- sends machine ARO-01 to MQTT
- behaves like the final boss-side sender for v1

What the PrediTeq platform does:
- in local rehearsal, your Windows PC runs the backend and frontend
- in production, Render and Vercel receive and display the data
- in both cases, ARO-01 updates Machine reelle

Files you should care about:
- run_mac_fake_csv_rehearsal.sh
- run_mac_real_csv.sh
- PREFERRED_LABVIEW_CSV_TEMPLATE.csv
- BRIDGE_CONFIG_EXAMPLE.txt

Recommended production use:
- copy BRIDGE_CONFIG_EXAMPLE.txt to BRIDGE_CONFIG.txt
- fill BRIDGE_CONFIG.txt with your private MQTT broker values
- the shell scripts will read BRIDGE_CONFIG.txt automatically
- for a low-cost continuous setup, start with PUBLISH_INTERVAL_S=5.0
- then the MacBook only needs the real CSV command

Typical use on the MacBook:

1. Copy this whole folder to the Desktop

2. Open Terminal in this folder

3. Make the two shell scripts executable:

   chmod +x run_mac_fake_csv_rehearsal.sh run_mac_real_csv.sh

4. Rehearsal with fake CSV:

   bash ./run_mac_fake_csv_rehearsal.sh

   This starts:
   - a fake CSV writer
   - the MQTT sender

5. Real CSV mode:

   bash ./run_mac_real_csv.sh "/absolute/path/to/real_labview_output.csv" ARO-01

   This first checks the CSV header, then starts the sender.

Using a private broker:
- by default the shell scripts use broker.emqx.io
- for the real setup, prepare BRIDGE_CONFIG.txt first

Example BRIDGE_CONFIG.txt:

   MACHINE_ID=ARO-01
   PUBLISH_TRANSPORT=mqtt
   MQTT_HOST=your-private-broker
   MQTT_PORT=8883
   MQTT_USER=your-user
   MQTT_PASSWORD=your-password
   MQTT_USE_SSL=true
   MQTT_TOPIC=prediteq/{machine_id}/sensors
   PUBLISH_INTERVAL_S=5.0
   SOURCE_LABEL=boss_macbook_csv

Manual override example:

   MQTT_HOST=your-private-broker \
   MQTT_PORT=8883 \
   MQTT_USER=your-user \
   MQTT_PASSWORD=your-password \
   bash ./run_mac_fake_csv_rehearsal.sh

Real CSV example:

   bash ./run_mac_real_csv.sh "/absolute/path/to/real_labview_output.csv" ARO-01

The real CSV script uses PUBLISH_INTERVAL_S from BRIDGE_CONFIG.txt.
If you do not set it, the default real-data interval is 5 seconds.

Important:
- use ARO-01 as the machine code
- in the app, ARO-01 appears as Machine reelle
- use fake data only with the public test broker
- for local rehearsal, keep the backend and frontend running on your own PC
- for production, point the bridge to your private broker and let Render/Vercel handle the app side
- do NOT copy prediteq_api/.env to the MacBook
- do NOT copy Supabase or backend secrets to the MacBook

If you want to review the expected CSV format:
- open PREFERRED_LABVIEW_CSV_TEMPLATE.csv

If you want to understand the bridge config:
- open BRIDGE_CONFIG_EXAMPLE.txt
